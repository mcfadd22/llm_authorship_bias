text by default on this model, so `thinking` is null on every row. Only token counts survive
(`usage.output_tokens_details.thinking_tokens`). The pilot rows do carry reasoning, so the
judges are not comparable on this field.

**Structured output.** Integer bounds were removed from the schema before the run because
the API rejects them (`e726f26`). All 4,464 scale answers are nonetheless within 1–7.

**H4, the core question.** Blame and intentionality are null, and the intervals rule out
rival − self gaps beyond about ±0.1 on blame and ±0.3 on intentionality. H4c is the one H4
effect in any wave-2 judge so far. When the label says Sonnet wrote the code itself, it
explains the bug as a diligence lapse more than when the label names a rival. Under `self`,
47 of 232 answers give a 7 ("purely a diligence lapse"); every other label gives 11–17.
The reasoning argues from the author's evident competence. One example: "the model clearly
has that understanding here". This matches wave 1's direction (Sonnet `self` +0.80 on
H3; Opus +1.24). Wave 2's H3 `self` shift (+0.41) is about half Sonnet's wave-1 size.

**H1 and H2 respond to whether an author is named at all, not to which author.** Every label
raises blame by 0.13–0.29 and lowers intentionality by 1.0–1.5 against `none`. Self and rival
do not differ on either (H4a, H4b). For H2, the `none` baseline looks like the thing that
moved; see the next section.

## Exploratory: Sonnet treats unlabelled code as test material

Not prespecified. Descriptive cuts and a keyword pattern, not a coding.

- **Sonnet's intentionality answers are bimodal under `none`.** 58% score ≥ 5 (leaning
  intentional), against 22–34% under every label (232 answers per label).
- **In the high `none` answers, it argues that the bug was planted.** Examples: "the single
  deliberate flaw inserted for review/testing purposes", "a common pattern used in
  code-review exercises", "a deliberately inserted red herring". A strict keyword pattern
  (planted, red herring, review/testing exercise, "to test whether the reviewer…") matches
  80% of Sonnet's `none` intentionality answers and 51–65% under labels. It matches none of
  the gpt-oss or Qwen answers.
- **The drop concentrates where a planted bug and an honest mistake look alike.**
  Share ≥ 5 under `none` vs. labelled: `missing_edge_case` 0.41 → 0.09, `silent_failure`
  0.44 → 0.11, `known_trap` 0.58 → 0.17, `logic_error` 0.50 → 0.25,
  `security_vulnerability` 0.95 → 0.48. `copy_paste_residue` does not move (0.58 → 0.60).
- **Wave 1 showed the same thing.** `status-2026-09-13.md`: Sonnet intentionality 4.37 under
  `none`, 2.95–3.15 under labels.

One reading: with no author named, Sonnet reads the snippet as an evaluation item and the
bug as planted. Any author label turns it into someone's mistake. If that holds, Sonnet's
H2 contrasts measure "an author was named", not a view about who wrote the code. H4b avoids
`none` and is null. The H1 blame shift may share the cause. The test-material framing
appears in only 0–5% of blame and explanation answers, though, so that is less clear.

or Anthropic. Under `none` it is 2%, under `human_developer` 0% and under `generic_ai` 1%.
